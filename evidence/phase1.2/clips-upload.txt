说明：
- 预检结论只写到界面上的「客户端预检」一行，明确标注「仅提示，最终以服务端判定为准」，不显示为「已可识别」。
- 容器时长读取失败时返回 null，界面提示「将不发送 durationMs」，不做码率估算或猜测。
- 客户端解析只读容器/头部（WAV data 块、FLAC STREAMINFO、MP3 Xing/Info/VBRI 总帧数、OGG granule、M4A mvhd），
  不等于完整解码，也不保证识破刻意伪造时长字段的文件；服务端探测为权威值。

二、授权（UploadConsent）
------------------------
- 调用 POST /api/v1/consents，body：{"scope":"RAW_AUDIO","purpose":"本机文件导入：上传原始音频用于识曲","retentionDays":7}
- 实测响应 201：scope=RAW_AUDIO、retentionDays=7、active=true、expiresAt=null（未设置到期时间，撤销前有效）
- 界面展示：授权 ID、scope、有效期、保留天数、状态；未创建有效授权时上传按钮不可用
  （disabled 条件包含 !consent?.active 与 !clipSelection?.accepted）。

三、上传（POST /api/v1/clips）
------------------------------
- 由主进程组 multipart/form-data 并附加 Authorization: Bearer <token>；文件路径与令牌均不进入渲染进程。
- 文本字段以 text/plain 提交；durationMs 为数值型 @RequestPart，以 application/json 提交（text/plain 会被判 415）。
- durationMs 仅在容器时长落在 500–300000 ms 内才附加；读取失败或超出区间时不传。
- 上传前先调用 POST /api/v1/consents/{id}/verify，避免把授权失效误判为「接口未上线」。
- 真实后端实测 201：
  clipId=<uuid>，format=WAV，sizeBytes=88244，durationMs=1000（服务端探测），status=STORED，
  expiresAt=上传时刻 + 7 天。

四、错误码逐类映射（本地假 HTTP 服务逐一验证，均不吞错误码）
------------------------------------------------------------
- 415：UNSUPPORTED_MEDIA_TYPE → 「格式不受支持：文件内容与扩展名/格式不一致，或不是可解析的音频容器（HTTP 415 / …）」
- 413：PAYLOAD_TOO_LARGE → 「文件实际字节超过 25 MB（HTTP 413 / …）」
- 400：VALIDATION_FAILED → 透传服务端消息（如客户端时长与实测偏差过大）并附状态码与 code
- 404：endpointMissing=true → 「后端尚未提供 /api/v1/clips 接口（HTTP 404），未上传任何文件」，界面显示「未上传」
- 403：CONSENT_REVOKED → 「上传授权已撤销、已过期或保留天数为 0，请重新创建授权（HTTP 403 / …）」
- 授权 verify 404 → 「上传授权不存在或不属于当前用户（HTTP 404 / …）」
- 401 → 清除本地会话（authenticated=false、persistence=memory），提示「登录已失效，请重新登录」
- 连接被拒 / 超时 → 分别提示「连接被拒绝：后端尚未启动或不可达」「请求超时」
真实后端在本批验证时已上线 /clips（返回 201），因此 404 分支只用本地假服务验证，未对真实缺失接口做实测。
